# 倉庫盤點工具

給 65 歲以上長輩用的手機盤點網頁。用下拉選單選商品，填箱、盒、袋的數量，完成後產生一張摘要圖，直接傳 LINE。

取代原本「用手機打開 Excel、放大找格子填數字」的做法，避免看錯列、填錯欄。

## 功能

- **選商品**：44 項商品內建在工具裡，可以打字搜尋（例如打「薑」只剩薑一壺）。已盤點過的商品會標示「已盤點」。
- **填數量**：每項商品都有箱、盒、袋三格（優質螺旋藻為箱、罐、袋），預設都是 0，可用 ＋／− 按鈕或直接打數字。
- **防呆**：盤點人名字必須填；數量格預設為 0，沒有的格子不用動。若把格子清空或名字沒填，會顯示紅框、提示哪一格沒填，並直接跳到那一格。
- **增加／減少**：同一商品再次輸入時可選增加或減少。例如盤到 10 盒，有人買走 3 盒，就輸入「減少 3 盒」，結果為 7 盒。不能減成負數。
- **分筆合併**：同一商品可以分多筆輸入（例如先填盒數、後填箱數），摘要圖會合併成一列。
- **修正**：每筆輸入都列在「已盤點」區，可以單筆刪除，合計自動重算。
- **摘要圖**：按「完成，產生摘要圖」，產生直式 PNG，內容包括：
  - 有庫存的商品與數量
  - 庫存為 0 的商品（醒目底色）
  - 這次沒有盤點到的商品
- **暫存**：資料存在手機瀏覽器，中途關掉再打開仍在。「清空」需連按兩次才會刪除。
- **固定淺色**：手機開深色／夜間模式（包含 Android Chrome 的「網頁強制深色」）也維持淺色底，不會變黑。
- **字體放大**：關閉瀏覽器自動放大字；手機系統字體調大造成整頁放大時（最高測到 200%），版面會改成直式排列，按鈕不會被擠出畫面。

## 盤點記法

每項商品記「完整箱數＋散裝盒數＋袋數」，不換算總量。貨架上有 2 整箱、5 盒散裝、3 袋，就記成 2 箱 5 盒 3 袋；沒有的包裝保持 0。只接受整數。

## 專案結構

| 路徑 | 說明 |
| --- | --- |
| `src/core.js` | 盤點核心邏輯（商品清單、合計、輸入檢查、摘要分區），不碰畫面 |
| `src/ui.js` | 畫面操作與摘要圖繪製，計算都交給 `core.js` |
| `src/app.html` | 版面與樣式 |
| `scripts/build.mjs` | 把 `src/` 組成單一檔案 `dist/index.html` |
| `scripts/package.mjs` | 打包 zip（只會在測試通過後執行） |
| `tests/unit/` | 單元測試（Node 內建 `node:test`） |
| `tests/e2e/` | E2E 測試（Playwright，模擬手機實際點擊） |

## 開發與測試

需要 Node.js 18 以上。

```bash
npm install
npx playwright install chromium   # 第一次跑 E2E 前需要
npm run build      # 產生 dist/index.html
npm run test:unit  # 單元測試
npm run test:e2e   # 建置後跑 E2E 測試
npm test           # 兩種測試都跑
npm run package    # 先跑全部測試，通過才打包 release/mei-inventory.zip
```

**單元測試涵蓋**：商品清單完整性（每項三格）、搜尋、數量輸入整理、＋／− 不低於 0、分筆合併、箱盒袋各自的增加與減少、舊資料相容、各種錯誤情況（名字空白、格子清空、減少全 0、減少超過現有數量）、刪除後重算、摘要三區分組、暫存讀寫與壞資料。

**E2E 測試涵蓋**（手機尺寸、實際點擊）：搜尋與收起鍵盤、選商品與換商品、輸入格預設 0、＋／− 按鈕、所有錯誤提示的紅框／訊息／跳到欄位與修正後消失、增加／減少切換、加入與合計、刪除需按兩次、摘要圖產生與分享提示、清空需按兩次、重新整理後資料保留、手機寬度不左右捲動、袋的增減與錯誤提示、手機深色模式與「強制深色」下仍為淺色（以實際畫面像素驗證）、整頁放大 130%／150%／200% 與 320 寬小螢幕的版面。

## 部署

這是靜態網頁，任何靜態主機都能放。

部署的是 `dist/index.html`（或 zip 裡的 `index.html`），單一檔案即可。

**Netlify（最簡單）**
1. 登入 Netlify，進入 Sites。
2. 把 zip 解壓後的資料夾拖進 Deploy 區。
3. 取得網址，傳給長輩，請他們在手機上「加入主畫面」。

**GitHub Pages**
1. 推上 GitHub repo。
2. 用 GitHub Actions 執行 `npm run build`，把 `dist/` 發布到 Pages；或把 `dist/index.html` 放到 Pages 使用的分支。
3. 網址為 `https://<帳號>.github.io/<repo 名稱>/`。

放在自己的網站後，「分享」按鈕可以直接叫出 LINE；若手機不支援，長按摘要圖即可儲存或分享。

## 維護商品清單

商品清單寫在 `src/core.js` 裡的 `const NAMES = [ ... ]`，一行一個商品名稱。每項預設三格：`UNITS = ["箱", "盒", "袋"]`。

少數商品的格子名稱不同，寫在 `UNIT_OVERRIDES`，例如：

```js
const UNIT_OVERRIDES = { "優質螺旋藻": ["箱", "罐", "袋"] };
```

- **新增商品**：在想要的位置加一行。
- **下架商品**：刪掉那一行。
- 清單順序就是下拉選單和摘要圖的順序。
- 改完請跑 `npm test`；單元測試會檢查商品數量，增減商品時要一併更新測試裡的數字。

> 注意：商品以「在清單中的位置」辨識。新增、刪除或調整順序後，請把 `STORAGE_KEY = "mei-inventory-v2"` 的版本號加一（例如改成 `v3`），讓手機上的舊暫存資料自動作廢，避免數字對到錯的商品。請在沒有人正在盤點時更新。

## 關於字體大小與深色模式

- **深色模式**：網頁宣告只使用淺色（`color-scheme: only light`），手機設成深色時不會變黑底。少數瀏覽器的強制深色若不理會這個宣告，請在該瀏覽器設定中對此網站關閉深色模式。
- **字體大小**：網頁已關閉瀏覽器的自動放大字（`text-size-adjust: 100%`），但手機的「無障礙字體放大」在新版 Chrome 和部分瀏覽器會直接整頁放大，網頁無法也不應該阻擋，否則需要大字的長輩會看不清楚。因此做法是讓版面在放大後仍好用：放大時三格數量會改成上下排列，按鈕維持可點的大小。

## 資料與隱私

- 沒有後端、沒有資料庫、不需要登入。
- 盤點資料只存在使用者自己的手機瀏覽器（localStorage），不會上傳到任何地方。
- 不讀取、也不寫入原本的 Excel 盤點檔。

## 不在第一版範圍

- 讀取或寫回 Excel
- 歷次盤點紀錄、與上次比較
- 箱與盒的換算
- 多人同時盤點
- 到期日記錄
